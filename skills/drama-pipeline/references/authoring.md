# Operating a project

1. Inspect existing artifacts and the brief. Do not regenerate completed work merely because the chat is new.
2. Initialize pipeline.json, then run resume. Produce the outline and show a concrete adaptation proposal. After user approval, record the outline checkpoint.
3. Author and validate characters/art, then screenplay in small episode batches. Maintain an aggregate screenplay artifact when extending batches so downstream completeness checks remain meaningful.
4. Author opening staging and its report. Generate character anchors when requested and a tool is available; record approval before derivatives. Register each character asset independently. With no image capability, leave a pending job and continue available text preparation.
5. Seed storyboard with staging and screenplay. Validate coverage, export a neutral pack, and list missing images explicitly.

After any edit, run status. Stale means the previous input snapshot no longer matches; read the changes, revise affected data, validate, then accept. Missing inputs, failed validation, and unanswered checkpoints are different outcomes and need different next actions. Do not use register/accept to conceal unreconciled creative changes.

The CLI does not invoke an Agent or launch subagents. Follow the current environment's tool availability and authorization when doing creative work. No hidden model calls or credentials are needed for offline status and validation.
